# UNUNKNOWNTUN 3.7.0-preview.8 · [English](README.md) · [Русский](README.ru.md) · [中文](README.zh-CN.md)

**Control Room UI (preview.10):** installer menu **9**, or `sudo bash UNUNKNOWNTUN-V3-INSTALLER-3.7.0-preview.11.sh ui`. It is embedded; no separate UI transfer is required. Opening it does not upgrade or restart tunnels.

Экспериментальная версия. Сохраните резервные копии обоих узлов и сначала
проверьте её на тестовом сервере. Рабочие серверы не изменялись; тесты Linux выполнялись в отдельной локальной виртуальной машине.

В preview.8 Direct ICMP поддерживает `off / fixed / adaptive` FEC. Новые пары по умолчанию используют adaptive; старые конфигурации без полей FEC остаются в режиме off. Обновите оба узла перед включением FEC. Дополнительные пакеты расходуют трафик и не обходят полную блокировку ICMP. [Настройка](docs/DIRECT-ICMP.md).

Новые возможности: независимые адрес подключения, TLS SNI и HTTP Host; ручное
или автоматическое получение ECH; фрагментация ClientHello; настраиваемый
padding WS/XHTTP; режимы XHTTP auto, packet-up, stream-up, stream-one; ограниченное
сканирование Cloudflare и добровольное периодическое обновление с откатом.

В 3.7 добавлены согласованная ротация резервных путей, постепенная замена сессий,
предварительный просмотр сканирования и отдельный Nginx на стороне origin без CDN.
[Настройка и ограничения](docs/ADVANCED-3.7.md).

**Пункт ClientHello через DNS удалён.** DNS-получение ECH сохраняется,
но не является DNS-туннелем. ECH настраивается на стороне, инициирующей TLS;
географическое расположение само по себе не определяет эту роль.

## Установка

В установочном архиве находятся Linux amd64/arm64 и автономный установщик:

```sh
sha256sum -c SHA256SUMS
sudo bash UNUNKNOWNTUN-V3-INSTALLER-3.7.0-preview.8.sh
```

Сначала настройте зарубежный egress, затем импортируйте его секретный код на
origin. Обновляйте оба управляемых узла согласованно: Upgrade заменяет общий
исполняемый файл. Не применяйте его для автоматического переноса отдельных
изолированных сервисов. Не публикуйте токены или конфигурацию серверов.

В готовом проверенном preview-архиве можно установить только отдельный версионный
бинарный файл без запуска служб. Обычная сборка исходников не создаёт этот дополнительный установщик:

```sh
python3 -I install-preview.py --dry-run
sudo python3 -I install-preview.py --install
```

Существующий GRE остаётся отдельной Linux-функцией для прямого TLS, без CDN.

## Управление

```sh
sudo ununknowntunctl list
sudo ununknowntunctl edit TUNNEL_ID
sudo ununknowntunctl cdn TUNNEL_ID
sudo ununknowntunctl cdn-scan TUNNEL_ID
sudo ununknowntunctl cdn-preview TUNNEL_ID
sudo ununknowntunctl cdn-status TUNNEL_ID
sudo ununknowntunctl ui
```

Замените TUNNEL_ID выбранным идентификатором. connect_host меняет адрес сети,
tls_sni — имя сертификата, http_host — HTTP-маршрут. Host должен совпадать с
настройкой второго узла/CDN; редактор выдаёт подписанный код синхронизации.

Автоматическое сканирование по умолчанию выключено. Можно задать длительность,
число адресов, список IPv4/CIDR Cloudflare и интервал. Ручные адреса доступны
также для Arvan/Fastly. Замена IP перезапускает только выбранный туннель и может
прервать сеансы. Успех сканера означает проверку сертификата, транспорта и
токена, но не скорость или полезный трафик клиента.

auto использует packet-up. Потоковые режимы требуют обновления обоих узлов и
проверки конкретного CDN; это не совместимый с обычным Xray/VLESS транспорт.
Padding расходует трафик и не гарантирует обход фильтрации.
Материалы проверки находятся в validation; исходники и тесты включены.
Ничего автоматически не опубликовано на GitHub.
