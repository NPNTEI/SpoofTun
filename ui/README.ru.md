# UNUNKNOWNTUN Terminal UI

[English](README.md) · [Русский](README.ru.md) · [简体中文](README.zh-CN.md)

Терминальный интерфейс для уже установленного UNUNKNOWNTUN с разделами **Tunnels**, **Tuning** и **Doctor**. Это версия интерфейса **3.7.0-preview.11**, сохраняющая структуру менеджера **3.5** и добавляющая необязательные действия **3.7**. Сам интерфейс — **не UNUNKNOWNTUN V1**, не новое ядро туннеля, не установщик обновлений и не веб-панель управления.

Проверка на действующих серверах не проводилась. При открытии интерфейс ничего не устанавливает, не переносит, не перезапускает и не проверяет удалённо. Все четыре руководства описывают одинаковое поведение; названия меню и команд приложения остаются на английском языке.

## Краткое руководство 3.7: адреса, ECH и padding

Страница Tuning отдельно показывает фактический **Dial endpoint**, **TLS SNI** и **HTTP Host**. Выбор чистого IP/домена изменяет адрес подключения, но сам по себе не меняет SNI и Host. Клавиша `e` открывает редактор выбранного туннеля. Вручную можно указать IPv4, IPv6 или домен; автоматическое сканирование диапазонов ограничено IPv4 Cloudflare, не Fastly/Arvan.

- `n` открывает настройки CDN (`cdn`): кандидаты, максимальная длительность, порог улучшения и необязательное периодическое обновление. Автообновление по умолчанию **выключено**; интервал — **8 часов**, бюджет сканирования — **300 секунд**, максимум — **600 секунд**.
- `s` передаёт сканирование и применение результата (`cdn-scan`) совместимому менеджеру. Операция может изменить адрес и перезапустить выбранный туннель; необходимо точно ввести его ID. Аутентификация не доказывает передачу клиентского трафика или пропускную способность.
- `v` показывает состояние CDN (`cdn-status`), не включая обновления и не запуская сканирование. Открытие и обновление экрана сами по себе ничего не сканируют и не изменяют.

Источник ECH отображается как автоматическое получение из DNS, вручную заданный дескриптор DNS/резолвера или ECHConfigList. Адреса/параметры резолвера и исходные байты скрыты. ECH используется TLS-клиентом, инициирующим соединение, и не привязан географически к Ирану; TLS-терминатор должен его поддерживать. **«TLS Hello over DNS» удалён из меню**; получение ECH через DNS сохранено и не является DNS-туннелем.

В 3.7 клавиша `p` запускает `cdn-preview`: прогресс сканирования без смены адреса или перезапуска. Tuning показывает ротацию путей и обновление сессий; `e` открывает согласованный профиль, интервал обновления и отдельный вход `nginx` без CDN. Для ротации обе стороны требуют 3.7, синхронные часы и одинаковые подписанные настройки. Вход Nginx требует согласованных WS/XHTTP-клиентов, не превращая TCP автоматически.

Видны режимы XHTTP `auto`, `packet-up`, `stream-up`, `stream-one` и оба значения padding. **Frame padding bytes** и **XHTTP HTTP padding** — разные настройки. Совместимость потоковых режимов с реальными CDN не подтверждена; проверяйте провайдера и режим реальным клиентским трафиком. Новые действия требуют соответствующих компонентов 3.7; неподдерживающий их старый менеджер отклоняется без автоматического обновления.

## Проверка пакета

Распакуйте полный ZIP-архив выпуска и откройте терминал в корне выпуска, содержащем `SHA256SUMS`, а не внутри `ui/`. Если архив только с исходниками не содержит манифест, используйте опубликованную контрольную сумму самого архива. Перед запуском проверьте файлы одного доверенного выпуска:

```bash
sha256sum -c SHA256SUMS
```

В macOS используйте `shasum -a 256 -c SHA256SUMS`. Контрольные суммы позволяют обнаружить изменения файлов, но не подтверждают их подлинность, если злоумышленник контролирует и файлы, и список контрольных сумм.

## Просмотр без доступа к серверу

Внутри каталога `ui/`, в macOS или Linux с Python 3.8 или новее:

```bash
python3 ununknowntun-ui.py --demo
```

Демонстрационный режим не требует прав root. Все данные приведены для примера, а любые действия с реальной установкой отключены. Введите клавишу или команду и нажмите Enter. Чтобы вывести один демонстрационный экран без интерактивного терминала:

```bash
python3 ununknowntun-ui.py --preview doctor
```

Полный выпуск может содержать `ui/preview.html`. Архиву только с исходниками готовые файлы макета не нужны. Чтобы создать новый локальный макет, выберите ещё не существующее имя файла:

```bash
python3 ununknowntun-ui.py --export-html ui-preview.html
```

Откройте `ui-preview.html` в браузере для просмотра трёх демонстрационных страниц. Это статический локальный макет, не действующая веб-панель и не результат диагностики; к серверам он не обращается.

## Запуск на существующем сервере

Для работы с реальной установкой нужны Linux, права root, Python 3.8 или новее, systemd и уже установленный менеджер UNUNKNOWNTUN. Интерфейс не использует сторонние библиотеки Python и ничего не устанавливает и не скачивает.

The installer now includes this UI: choose **9) Control Room UI** in its main menu. After a normal install or upgrade, open it directly:

```bash
sudo ununknowntunctl ui
```

To open the embedded UI without installing or upgrading anything, run:

```bash
sudo bash UNUNKNOWNTUN-V3-INSTALLER-3.7.0-preview.11.sh ui
```

Guided rounds (`b` / `cdn-rounds`) use the selected tunnel's port and SNI, ask for range/count and per-round probes/workers/maximum latency, show live results, and allow repeated Top-N refinement. Ctrl+C retains completed results. Choosing an endpoint runs the existing authentication and transactional apply checks; automatic scanning policy is unchanged. Direct ICMP endpoints remain isolated from standard tunnel actions. Press **i** to open their dedicated manager, available even when no standard tunnel is registered; use the installer's **8) ICMP L3** for setup.

При первом открытии интерфейс только считывает локальную конфигурацию и состояние служб. Он не заменяет `/usr/local/bin/ununknowntunctl`, исполняемый файл ядра, Nginx, X-UI, правила межсетевого экрана, сертификаты, порты или файлы сопряжения. Для соответствующих действий нужны установленные редактор и вспомогательные инструменты Doctor; неподдерживаемые команды менеджера отклоняются, а не считаются успешно выполненными.

## Управление

Введите одну из следующих команд и нажмите Enter:

| Команда | Действие |
|---|---|
| `1` | Страница Tunnels |
| `2` | Страница Tuning |
| `3` | Страница Doctor |
| `t 2` | Выбрать второй туннель в списке |
| `e` | Открыть существующий полнофункциональный редактор для выбранного туннеля |
| `a` | Открыть существующий процесс обновления сопряжённых серверов с помощью кода обновления |
| `c` | Открыть существующий интерфейс управления клиентами, портами и квотами |
| `u` | Показать статистику использования через установленный менеджер |
| `o` | Запустить, остановить, перезапустить или удалить выбранный туннель |
| `n` | После точного ввода ID открыть настройки адреса CDN и периодического сканирования |
| `b` | Guided Cloudflare scan rounds, refine Top-N and select an authenticated endpoint; exact tunnel ID required |
| `p` | Preview the authenticated CDN scan without changing the endpoint |
| `s` | После точного ввода ID сканировать/применить адрес; возможен перезапуск этого туннеля |
| `v` | Показать настройки/состояние CDN без запуска сканирования |
| `k` | Открыть полный сканер SIKDPI: IP, SNI, REALITY, скорость и экспорт; выбор туннеля не требуется |
| `i` | Open Direct ICMP management: endpoint list, forwarding information, status, start/stop/restart, logs, doctor and removal |
| `f` | Проверить конфигурацию без сетевых запросов с помощью установленного Doctor |
| `d` | После подтверждения проверить настроенные конечные точки этого туннеля |
| `r` | Обновить локальное состояние и убрать с экрана предыдущие отчёты |
| `q` | Выйти из интерфейса |

Полный сканер открывает мастер на английском языке через `ununknowntunctl scanner`. Само открытие не запускает сетевое сканирование и не устанавливает зависимости. Перед проверкой нужно указать цели и подтвердить разрешение; отчёты сохраняются приватно, результаты никогда не применяются к туннелю UNUNKNOWNTUN. Доступность TLS/SNI, аутентифицированное соединение REALITY и аутентификация UNUNKNOWNTUN — разные уровни доказательств. Существующая команда `s` сохраняет сканирование и применение CDN-адреса; `k` её не включает. Деморежим блокирует `k`, как и остальные действия с реальной системой.

Перед открытием операции, которая может вносить изменения, введите точный идентификатор выбранного туннеля. Пустое подтверждение отменяет операцию. Существующий редактор по-прежнему показывает предварительный результат и запрашивает подтверждение отдельных изменений, обеспечивает блокировку и откат, а при необходимости формирует обновления для сопряжённых серверов. При удалении также сохраняется существующая процедура подтверждения и резервного копирования в менеджере.

Редактирование, остановка или перезапуск могут прервать работу выбранного туннеля. Читайте вывод операции: нулевой код завершения сам по себе не доказывает, что клиенты могут подключиться. Формы управления клиентами и редактирования по-прежнему используют существующие интерфейсы; их внешний вид ещё не был полностью переработан.

## Управляемые службы и службы только для просмотра

Стандартные туннели, зарегистрированные в `/etc/ununknowntun/tunnels`, можно выбирать для управления, если их конфигурация доступна для чтения и считается доверенной. Устаревшие или отдельно установленные службы, включая `ununknowntun.service`, `ununknowntun-germany.service` и `ununknowntun35-turkey-yta.service`, отображаются **только для просмотра**. Интерфейс никогда автоматически не берёт их под управление и не обновляет.

Создание новых туннелей и обновление ядра остаются задачами существующего установщика; эта предварительная версия его не запускает. Не смешивайте файлы и данные сопряжения UNUNKNOWNTUN V1 и 3.x. Этот интерфейс не обеспечивает совместимость V1 со структурой менеджера 3.5.

Отображаемые настройки — это сохранённая конфигурация, а не доказательство успешного согласования ECH, MUX или установления соединения. Небезопасная или недоступная для чтения конфигурация блокирует действия. Если конфигурация изменилась после выбора туннеля, обновите её отображение и проверьте перед продолжением.

## Как понимать диагностику

- `active/running` описывает состояние процесса службы, а не работоспособность туннеля или подключения к Интернету.
- `WAIT` означает, что проверка ещё не выполнялась. `PASS` берётся из фактического отчёта Doctor, а не служит демонстрационной отметкой успеха.
- Успешная проверка TLS или аутентификации туннеля не доказывает, что работают VLESS, Shadowsocks или передача трафика реальных сайтов. Пункт **Real client payload** остаётся в состоянии `TODO` и требует отдельной проверки с клиентом.

Doctor использует соответствующий установленный вспомогательный инструмент и проверяет только настроенные конечные точки. Он не сканирует диапазоны портов, не отключает проверку TLS и не переписывает конфигурацию. Интерфейс отводит **55 секунд на весь запуск** и **3 секунды на каждый этап**. Медленные соединения или большое число проверяемых вариантов могут привести к превышению этого лимита; незавершённая проверка не считается успешной и не устанавливает причину сбоя. Для более длительной диагностики используйте существующий CLI. Автономный режим не выполняет сетевых проверок.

Отчёты представляют собой снимки состояния с отметкой времени, а не непрерывный мониторинг. Ошибки конечных точек указывают на этап, на котором произошёл сбой; интерфейс не делает предположений о том, что причина обязательно в токене, сертификате или межсетевом экране.

## Отображение и секретные данные

Фон и шрифт задаются в Termius или вашем терминале. Точное воспроизведение белого оформления концептуального изображения не гарантируется. Для удобного чтения рекомендуется окно шириной не менее 80 столбцов и высотой около 40 строк; в невысоком окне прокручивайте вывод вверх. Используйте `--ascii` при ограниченной поддержке символов шрифтом или `--no-color` для вывода без цвета. Переменная `NO_COLOR` также учитывается.

Главный экран и статический макет не показывают токены, `peer.env`, закрытые ключи или приватные маршруты туннелей. Подробности диагностики берутся из отчёта установленного Doctor, очищенного от секретных данных. После изменения существующий редактор может показать конфиденциальный код синхронизации: не публикуйте этот код или снимки экрана, содержащие секретные данные.

## Проверка и выход

Запустите входящие в пакет автономные тесты интерфейса:

```bash
python3 test_terminal_ui.py
```

Тесты используют подготовленные данные и имитации служб, а не реальные серверы или сеть. Полный набор запускается командой `python3 run-tests.py` из `source/ui/` (или `ui/` в архиве исходников GitHub); рядом должен находиться соответствующий каталог `packaging/`. Отдельная копия интерфейса не запускает интеграцию совместимости. В корне полного выпуска `VALIDATION.md` и `validation/` описывают проверки и ограничения, а `SHA256SUMS` охватывает поставляемые файлы. Эти сгенерированные отчёты не обязательны в архиве только с исходниками. Локальные тесты не заменяют приёмочную проверку Linux; сначала используйте непроизводственный сервер.

Нажмите `q` для выхода. У интерфейса нет фоновой службы или записи автозапуска; его закрытие не останавливает туннели. После выхода удаление файла этого вспомогательного интерфейса не удаляет ядро туннеля или его конфигурацию. **Не заменяйте им `ununknowntunctl`.**

## Direct ICMP management

Use `--icmp-manage --list` for a read-only inventory without an interactive terminal. The **i** shortcut and `--icmp-manage` open the trusted `direct-icmp-console.py` staged beside the UI. The matching installer and installed `ununknowntunctl ui` stage both files. Source-only `--preview` and `--demo` do not need this helper; live management requires the installed/staged pair. Opening the console only reads `/etc/ununknowntun-direct-icmp`; it performs no migration, scan, installation or service change. Configured local and remote forwarding ports appear in the endpoint list.

Each action uses the selected endpoint's own verified manager. Older valid endpoints remain on their existing version; unsupported actions are refused without upgrading or substituting a restart. Start, stop, restart and removal require the exact `pair/role` identity. Removal affects only that local endpoint, not its peer. Demo mode blocks **i**. Service status is not proof of payload delivery; Doctor and real-client checks remain separate.
